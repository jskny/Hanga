# エッジケースの検証(Hanga.EdgeCases)

不具合が起きやすい帳票・使い方を集めたサンプルです。各ケースを `HangaBatch`(Web アプリとは別の実行ファイルの形)で順に生成し、
期待どおりの結果(成功・例外・警告・時間)になるかを表にして出します。期待は「こう動くべき」という理想の動作で書いてあり、現状の動作には合わせていません。

ページの表示から PDF までの処理(ビューの描画・静的ファイル・JavaScript・待機・体裁)は、Web アプリの PDF 用アクションとバッチで共通です。
そのため、このサンプルの結果は Web アプリで使う場合にも当てはまります(オペレーターの Cookie の引き継ぎを除く)。

## 実行

リポジトリのルートで実行します。

```bash
dotnet run --project samples/Hanga.EdgeCases -- --chromium <Chromium の実行ファイル> [--arg --no-sandbox] [--gaiji-font IPAmj明朝] [--out <フォルダ>] [--only <番号の先頭>]
```

- 各ケースの PDF と結果の表(`results.md`)を、`--out` のフォルダ(既定は一時フォルダの `hanga-edge-cases`)に出します。
- 終了コードは、期待と違う結果(応答なしを含む)の件数です。0 なら、すべて期待どおりです。
- 待機の上限は 10 秒にしてあります(時間切れのケースを速く終えるため)。全体で 2〜3 分かかります。
- `--only J` のように番号の先頭を指定すると、そのケースだけを実行します。

## ケースの一覧

| 分類 | 番号 | 確かめること |
|---|---|---|
| 表示 | D01〜D08 | 大量の明細(3000 行)、1 ページ化の上限、明細 0 行、改行できない長い文字列、モデルに HTML・スクリプトの文字列、`Html.Raw` で外部の画像、特殊な文字(外字・異体字・絵文字・結合文字・ゼロ幅・アラビア語・制御文字・単独のサロゲート)、10 万文字の本文 |
| 静的ファイル | S01〜S03 | 日本語・空白入りのファイル名、CSS の `@import` と相対パスの `url()`、クエリ付きの URL、`data:` URL、存在しない画像 |
| JavaScript | J01〜J10 | `alert`・`confirm`・`window.print`、表示の後のページの移動、無限ループとその直後の生成、ポーリング、スクリプトの例外、遅れた描画、`document.write` |
| ビュー | V01〜V08 | レイアウトなし、必須のセクションの書き忘れ、部分ビュー、エリアのビュー、POST のフォーム、ログインユーザー・クエリ、存在しないビュー、モデルの型の誤り |
| 保存・並行・寿命 | P01〜P09 | 日本語の保存先、同じ保存先への並行した保存、存在しないフォルダ、30 件の並行、枠を待っている間の取り消し、`HangaBatch` を 2 つ、起動と終了の繰り返し、生成中の終了、相対パス |

## 結果(2026年10月4日、Linux、Chrome 141、外字用フォント IPAmj明朝)

38 件すべて期待どおり(下記の修正の後)。主な結果:

| 番号 | ケース | 結果 |
|---|---|---|
| D01 | 大量の明細(3000 行) | 成功(55 ページ、約 4.5 秒) |
| D02 | 1 ページ化で用紙の高さの上限を超える | 成功(4 ページ。`SinglePageOverflow` の警告) |
| D07 | 特殊な文字 | 成功(絵文字・アラビア語などを `MissingGlyph` の警告) |
| D08 | 10 万文字の本文 | 成功(27 ページ、約 4.2 秒) |
| J01・J02 | `alert`・`confirm` | 成功(「OK」で閉じて続ける。`Dialog` の警告) |
| J04 | 表示の後のページの移動 | 成功(移動を止めて元のページ。`BlockedNavigation` の警告) |
| J05・J06 | 無限ループ | 待機の上限で `HangaTimeoutException`。直後の生成も正常(同時処理数の枠は返る) |
| J07 | ポーリング | `HangaTimeoutException`(通信が止まないため。仕様どおり。利用の手引きに記載) |
| P02 | 同じ保存先に 10 件を並行して保存 | すべて成功、保存先は正しい PDF、一時ファイルは残らない |
| P04 | 30 件を並行(同時処理数 4) | 成功(約 0.34 秒/件)、取り違えなし |
| P08 | 生成中に終了 | 終了は約 0.1 秒、生成中の帳票は `HangaBrowserException` で終わる |

## この検証で見つかり、直した問題

| 問題 | 影響 | 対応 |
|---|---|---|
| `ViewAssemblies` を指定しないと、バッチのビューが自動で見つからない | 利用の手引きで推奨した使い方(Web の SDK のバッチで `ViewAssemblies` を省略)が動かない | アプリの名前をバッチの実行ファイルの名前にする(`batch-pdf-generation` のタスク8) |
| `alert`・`confirm` を出す画面が、毎回時間切れになる | ブラウザで印刷していた画面がそのまま PDF にできない | 「OK」で閉じて続け、警告にする(`view-pdf-generation` の要件4.6) |
| 表示の後に別の URL へ移動する画面で、移動先の内容の PDF を黙って返す | 帳票と違う内容の PDF が出る | 移動を止めて元のページを PDF にし、警告にする(要件2.7) |
| 1 ページ化で用紙の高さの上限を超えると、黙って複数ページになる | 指定と違う結果に気づけない | 警告にする(要件5.5) |

## 注意

- ビューコンポーネントは使っていません。.NET 10 SDK で `net5.0` 向けにビルドすると、Razor のコンパイラが失敗するためです(`docs/開発環境メモ.md`)。
- 静的ファイルは、ビルドの出力にコピーして使っています(`Hanga.EdgeCases.csproj`)。Web の SDK は、ビルドでは `wwwroot` を出力にコピーしないためです。
