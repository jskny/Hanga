# ライブラリの使い方

Hanga は、ASP.NET Core 5 MVC アプリのビュー(`.cshtml`)を、画面と同じ見た目の PDF にするライブラリです。
主な使い方は、コントローラーに PDF 用のアクションを追加し、オペレーターがそれを呼ぶと、画面と同じビューを PDF にしたものを返す、というものです。

- 対象: .NET 5(`net5.0`)の ASP.NET Core MVC アプリ。Visual Studio 2019 でビルドできます。
- 仕組み: ビューを画面と同じ仕組みで HTML にし、ヘッドレスの Chromium で表示して PDF にします。
  ビューが読み込む CSS・JavaScript・画像や、JavaScript が表示時に呼ぶ API は、アプリ自身の処理に(ネットワークを通さずに)渡されます。
  オペレーターのログイン(Cookie)を引き継ぐため、ログインが必要な API の値も PDF に入ります。
- Web アプリとは別の実行ファイル(バッチ)の中で、帳票を一括で PDF にすることもできます(「9. バッチでの一括生成」)。

## 1. 本番環境に必要なもの

| もの | 内容 |
|---|---|
| Chromium | Google Chrome・Chrome for Testing など。PDF を作るサーバーにインストールし、実行ファイルの場所を設定します。Hanga がダウンロードすることはありません |
| 外字用フォント(使う場合) | 人名・住所の外字や異体字を出すなら、IPAmj明朝 などをサーバーにインストールし、名前を設定します |
| 帳票の本文のフォント | ビューの CSS が指定するフォント(MS P ゴシック等)を、サーバーにインストールします |

Chromium は運用部門がバージョンアップする前提です。更新の前に `docs/Chromium更新前の検証手順.md` の手順で確かめてください。

## 2. 参照と登録

Hanga はソースツリー内から参照します(NuGet パッケージとしての配布は行っていません)。

```xml
<ProjectReference Include="..\Hanga\src\Hanga\Hanga.csproj" />
```

`Startup.ConfigureServices` で登録します。`Startup.Configure` の変更は不要です。

```csharp
public void ConfigureServices(IServiceCollection services)
{
    services.AddControllersWithViews();
    // ... 認証など

    // appsettings.json の "Hanga" 節から読む
    services.AddHanga(Configuration.GetSection("Hanga"));
}
```

```json
{
  "Hanga": {
    "ChromiumExecutablePath": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
    "GaijiFontFamily": "IPAmj明朝",
    "MaxConcurrentRenders": 4,
    "RenderTimeout": "00:00:30"
  }
}
```

コードで指定することも、設定ファイルの値をコードで上書きすることもできます。

```csharp
services.AddHanga(options => options.ChromiumExecutablePath = @"C:\...\chrome.exe");
services.AddHanga(Configuration.GetSection("Hanga"), options => options.Strict = true);
```

設定の値は登録時(アプリの起動時)に検証され、誤りがあれば `HangaConfigurationException` になります。設定ファイルの値を変えた場合は、アプリの再起動で反映されます。

### アプリ全体の設定(`HangaOptions`)

| 名前 | 既定 | 内容 |
|---|---|---|
| `ChromiumExecutablePath` | (必須) | Chromium の実行ファイルの場所 |
| `ChromiumArguments` | 空 | Chromium に渡す追加の起動引数(必要な場合のみ。下記「4. 注意点」) |
| `LaunchOnStartup` | `false` | アプリの起動時に Chromium を起動しておく(最初の PDF の待ち時間が短くなる。起動できなければアプリの起動が失敗する) |
| `MaxConcurrentRenders` | 4 | 同時に処理する帳票の数(下記「同時に処理する帳票の数の決め方」) |
| `RenderTimeout` | 30秒 | 表示の完了を待つ上限 |
| `AllowedExternalHosts` | 空 | ビューがインターネット上から読み込むことを許すホスト(既定はすべて遮断) |
| `GaijiFontFamily` | 未指定 | 外字用フォントの名前(インストール済みのもの)。推奨 |
| `GaijiFontFile` | 未指定 | 外字用フォントのファイル(名前で指定するより遅い) |
| `DetectMissingGlyphs` | `true` | どのフォントにも字形の無い文字(□で表示される文字)を検出する |
| `Strict` | `false` | 警告の対象をエラーにする(下記「5. 警告と厳格な扱い」) |
| `MaxResponseBodyBytes` | 50MB | ビューが読み込むファイル・API の応答 1 件の大きさの上限 |
| `MaxTotalResponseBytesPerReport` | 200MB | 帳票 1 件で、ビューが読み込むファイル・API の応答の合計の上限 |
| `VirtualOrigin` | `https://hanga.invalid` | Hanga が内部で使う仮想のオリジン(通常は変えない) |

## 3. PDF 用アクションの書き方

```csharp
public class OrdersController : Controller
{
    // 画面
    public IActionResult Detail(int id) => View(_orders.Find(id));

    // 同じビューを PDF にして返す
    public async Task<IActionResult> DetailPdf(int id)
    {
        var pdf = new Cshtml2Pdf(this, "Detail", _orders.Find(id));
        pdf.Options.Orientation = PageOrientation.Landscape;          // 横向き(既定は A4 縦)
        return await pdf.ToActionResultAsync("注文明細.pdf", PdfDisposition.Inline);
    }
}
```

- `new Cshtml2Pdf(this, ビュー名, モデル)`: コントローラーのフォルダ(`Views/Orders/`)からビューを探します。コントローラーの `ViewData`・`ViewBag` も引き継ぎます。
  ビュー名の代わりに `~/Views/Reports/Detail.cshtml` のようなパスも指定できます。
- `new Cshtml2Pdf(HttpContext, コントローラー名, ビュー名, モデル)`: 別のコントローラーのビューを使う場合や、コントローラーの外から使う場合。
- `Cshtml2Pdf` は帳票 1 件ごとに作ります(スレッドセーフではありません)。PDF を作る処理そのもの(Chromium など)はアプリ全体で共有され、複数のオペレーターが同時に使えます。
- ビューは、画面用のものをそのまま使えます。レイアウト(`_Layout.cshtml`)、`~/` のパス、タグヘルパー、印刷用の CSS(`@media print`)が画面・印刷と同じように扱われます。

### PDF の返し方

| メソッド | 内容 |
|---|---|
| `ToActionResultAsync(ファイル名, PdfDisposition.Inline)` | ブラウザで開く形で返す |
| `ToActionResultAsync(ファイル名, PdfDisposition.Attachment)` | ダウンロードさせる形で返す |
| `ToBytesAsync()` | バイト列で受け取る |
| `WriteToAsync(stream)` | ストリームに書き込む |
| `SaveAsync(path)` | ファイルに保存する(失敗した場合はファイルを作らない) |
| `GenerateAsync()` | PDF と警告の一覧(`HangaPdfDocument`)を受け取る |

ファイル名には日本語を使えます(`Content-Disposition` に UTF-8 の名前と ASCII の代替名の両方を付けます)。
取り消し(`CancellationToken`)を渡さなければ、オペレーターがブラウザを閉じたときに処理を中止します。

### 帳票ごとの体裁(`pdf.Options`)

| 名前 | 既定 | 内容 |
|---|---|---|
| `PaperSize` | `PaperSize.A4` | `A3`・`A4`・`A5`・`B4`・`B5`(JIS)・`Letter`・`Legal`、または `PaperSize.Custom(幅mm, 高さmm)` |
| `Orientation` | `Portrait` | `Landscape` で横向き |
| `Margins` | 上下左右 10mm | `PageMargins.Uniform(15)` や `new PageMargins(上, 右, 下, 左)` |
| `Scale` | 1.0 | 拡大縮小の倍率(0.1〜2.0) |
| `FitToPageWidth` | `true` | 画面の幅が用紙に収まらないときだけ縮小する。`false` で無効 |
| `SinglePage` | `false` | 画面の全体を 1 ページにする |
| `CssMedia` | `Print` | `Print`(印刷用の CSS)/ `Screen`(画面の見た目のまま) |
| `PrintBackground` | `true` | 背景色・背景画像を出力する |
| `PageNumbers` | `false` | フッターにページ番号(「1 / 3」)を出す |
| `Title` | 未指定 | PDF の文書のタイトル(未指定ならページの `<title>`) |
| `ReadyExpression` | 未指定 | 表示の完了の条件として待つ JavaScript の式(下記) |
| `Timeout` / `Strict` | 未指定 | アプリ全体の設定を、この帳票だけ上書きする |

### JavaScript で描画する画面

- 表示時に JavaScript が API から値を取得する画面は、その通信が終わる(約 0.5 秒間、新しい通信が無い)まで待ってから PDF にします。
- タイマー(`setTimeout`)で遅れて描画するなど、通信を伴わない描画は待てません。描画の完了をページ側で知らせ、`ReadyExpression` で待ちます。

  ```javascript
  // ビューの JavaScript
  drawChart().then(() => { window.reportReady = true; });
  ```

  ```csharp
  pdf.Options.ReadyExpression = "window.reportReady === true";
  ```

- ボタン操作などの後に取得する値は、PDF には入りません。

## 4. 注意点

- **API の呼び出し**: ビューの JavaScript が呼ぶ API は、相対パス(`/api/...`)で書かれている必要があります。オペレーターのログイン(Cookie)を引き継いで、アプリの中で処理されます。
- **失敗する API**: API が失敗した場合(400 以上)や、ログイン画面へ転送された場合(ログインの期限切れなど)は、値が欠けた PDF を返さず、`HangaResourceRequestException` になります。
- **インターネット上のファイル**: CDN などから CSS・JavaScript を読み込むビューは、`AllowedExternalHosts` にホストを加えない限り、その読み込みが遮断されます(既定では警告)。
  許可したホストからの読み込みが失敗した場合は、エラーになります。
- **PDF 用アクションの入れ子**: 帳票のビューから PDF 用アクションを読み込まないでください(iframe など)。Hanga が検出してエラーにします。
- **`ReadyExpression`**: ページの中でオペレーターの権限で実行されます。開発者が書いた固定の式だけを指定し、利用者の入力を含めないでください。
- **バイナリの本文**: ファイルのアップロードのように、バイナリの本文を送る API の呼び出しは、帳票の表示中には正しく転送できません。
- **Chromium の起動引数**: 通常は不要です。サーバーの環境でサンドボックスが使えない場合などに限り、運用部門と相談して `ChromiumArguments` に指定します。
- **URL のクエリ**: 例外・警告・ログに載せる URL からは、クエリ文字列を除いています(秘密の値が含まれうるため)。

### 同時に処理する帳票の数の決め方

Chromium は、待機中で約 700MB、同時に処理する帳票 1 件ごとに約 65〜130MB のメモリを使います(Linux での計測。`design.md`「同時に処理する帳票の数」)。
上限を決める主な要因はメモリです。目安は次のとおりです。

```
MaxConcurrentRenders ≒ (Chromium に使わせてよいメモリ − 700MB) ÷ 130MB
```

Windows Server ではメモリの使い方が異なる可能性があります。検証環境で計測して、`appsettings.json` で調整してください。

## 5. 警告と厳格な扱い

次の問題は、既定では**警告**として記録し、PDF は作ります。

| 警告(`HangaWarningKind`) | 内容 |
|---|---|
| `BlockedExternalRequest` | 許可していない外部(インターネット上)への読み込みを遮断した |
| `ScriptError` | ビューの JavaScript で例外が発生した |
| `MissingGlyph` | どのフォントにも字形の無い文字がある(□で表示されるおそれ。文字と符号位置を記録) |

警告はアプリのログ(`ILogger`)に記録され、`GenerateAsync()` の戻り値の `Warnings` でも受け取れます。
ログ(Warning)には警告の種類と件数だけを出し、詳細(字形の無い文字、スクリプトの例外の内容)は Debug レベルに出します(氏名などを含みうるため)。
`Strict = true`(アプリ全体の設定、または帳票ごとの `pdf.Options.Strict`)にすると、警告の対象を `HangaStrictModeException` にします。

## 6. 例外

すべて `HangaException` の派生で、失敗した段階(`Stage`)を持ちます。例外のメッセージにオペレーターの Cookie などは含めません。

| 例外 | 起きる場合 |
|---|---|
| `HangaConfigurationException` | 設定の誤り。外字用フォントがサーバーに無い。`AddHanga` を呼んでいない |
| `HangaViewNotFoundException` | ビューが見つからない(探した場所の一覧付き) |
| `HangaViewRenderingException` | ビューの描画中に例外が発生した(元の例外付き) |
| `HangaBrowserException` | Chromium を起動できない・Chromium への命令が失敗した(実行ファイルの場所と版付き) |
| `HangaResourceRequestException` | ビューが読み込むファイル・API の応答が失敗した(URL と状態コード付き) |
| `HangaTimeoutException` | 上限時間までに表示が完了しなかった(待っていた条件と、完了していなかった要求付き) |
| `HangaStrictModeException` | 厳格な扱いで、警告の対象が見つかった(警告の一覧付き) |

## 7. 外字・異体字

`GaijiFontFamily` に外字用フォント(IPAmj明朝 など)の名前を設定すると、帳票の本文のフォントに無い文字(「𠮷」など)と、
異体字セレクタ付きの文字(「葛」+U+E0102 など)を、外字用フォントで描きます。それ以外の文字は本文のフォントのままです。

- 外字用フォントの字形は明朝体のため、ゴシック体の本文の中では、その文字だけ書体が変わります。
- 設定したフォントがサーバーに無い場合は、Chromium の起動時に `HangaConfigurationException` になります。
- どのフォントにも字形の無い文字は、`MissingGlyph` の警告で知らせます(OS が別のフォントで代わりに描ける文字も、知らせる対象に含めます)。

## 9. バッチでの一括生成

Web アプリとは別の実行ファイル(バッチ)の中で、帳票のビューとモデルから PDF を作り、1 件ずつファイルに保存できます。
バッチはアプリケーションサーバー(Web アプリ)にアクセスしません。ブラウザで画面を開いて操作するものでもありません。
Hanga が、ビューを描画する仕組みと Chromium をバッチのプロセスの中に用意します(Web サーバーは起動せず、ポートも開きません)。
仕様は `.kiro/specs/batch-pdf-generation/` にあります。

### バッチで使える帳票の条件

バッチにはオペレーターがいないため、次の情報は使えません。帳票に載せる値は、**すべてモデルで渡す**作りにしてください。

- ログインユーザー(`User`)、セッション(使うと `HangaViewRenderingException`)、Cookie、要求のクエリ文字列
- Web アプリの API(JavaScript から呼ぶもの)。バッチの中には無いため、呼ぶと `HangaResourceRequestException` になります

### 帳票ライブラリとバッチのプロジェクト

帳票のビューと静的ファイル(CSS・JavaScript・画像)を **帳票ライブラリ**(Razor クラスライブラリ)にまとめ、Web アプリとバッチの両方から参照する形を推奨します。
帳票を 1 か所で直せば、画面とバッチの両方に反映されます。

帳票ライブラリ(例: `Reports.csproj`):

```xml
<Project Sdk="Microsoft.NET.Sdk.Razor">
  <PropertyGroup>
    <TargetFramework>net5.0</TargetFramework>
    <AddRazorSupportForMvc>true</AddRazorSupportForMvc>
  </PropertyGroup>
  <ItemGroup>
    <FrameworkReference Include="Microsoft.AspNetCore.App" />
  </ItemGroup>
</Project>
```

```
Reports/
├── Views/
│   ├── _ViewImports.cshtml
│   ├── _ViewStart.cshtml          @{ Layout = "_ReportLayout"; }
│   ├── Shared/_ReportLayout.cshtml 帳票用のレイアウト(帳票ライブラリに置く)
│   └── Invoice/Invoice.cshtml      帳票のビュー
└── wwwroot/
    └── css/report.css
```

- 静的ファイルは `~/_content/<ライブラリ名>/...`(例: `~/_content/Reports/css/report.css`)で参照します。Web アプリとバッチで同じ URL になります。
- レイアウトは帳票ライブラリに置いてください。Web アプリの `_Layout.cshtml` はバッチからは見えません。
- 帳票の本文のフォントは CSS で指定してください(指定が無いと、日本語が `MissingGlyph` の警告の対象になります)。

バッチ(例: `InvoiceBatch.csproj`)は **`Microsoft.NET.Sdk.Web`** で作ります。出力は普通のコンソールアプリで、Web サーバーは起動しません。

```xml
<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net5.0</TargetFramework>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\Hanga\src\Hanga\Hanga.csproj" />
    <ProjectReference Include="..\Reports\Reports.csproj" />
  </ItemGroup>
</Project>
```

この SDK なら、帳票ライブラリのビューが自動で見つかり、発行(`dotnet publish`)したときに静的ファイルが `wwwroot/_content/<ライブラリ名>/` に置かれます。
Visual Studio からの実行(ビルドの出力)でも、帳票ライブラリの `wwwroot` が使われます(Linux の .NET 5 ランタイムで確認。Visual Studio 2019 での確認は検証環境で行う予定)。
普通のコンソールアプリの SDK(`Microsoft.NET.Sdk`)で作る場合は、下の `ViewAssemblies` と `StaticFileMappings` の指定が必要です(根拠: `docs/PDF出力方式検証レポート.md`「6.5」)。

### 起動・生成・終了

```csharp
public static async Task<int> Main(string[] args)
{
    // 設定は Web アプリと同じ HangaOptions。appsettings.json の "Hanga" 節から読む場合
    var configuration = new ConfigurationBuilder()
        .SetBasePath(AppContext.BaseDirectory)
        .AddJsonFile("appsettings.json")
        .Build();
    var options = new HangaOptions();
    configuration.GetSection("Hanga").Bind(options);

    // 起動(Chromium もここで起動する。設定の誤り・Chromium の起動の失敗はここで例外になる)
    await using var batch = await HangaBatch.StartAsync(options, b =>
    {
        b.ViewAssemblies.Add(typeof(InvoiceModel).Assembly);                     // 帳票ライブラリ(Microsoft.NET.Sdk.Web なら省略可)
        b.ConfigureServices = services => services.AddLogging(l => l.AddConsole()); // ログの出力先、@inject で使うサービスなど
    });

    int failures = 0;
    foreach (var customer in LoadCustomers())
    {
        var pdf = new Cshtml2Pdf(batch, "Invoice", "Invoice", BuildInvoiceModel(customer)); // コントローラー名・ビュー名・モデル
        pdf.Options.PaperSize = PaperSize.A4;                                                 // 体裁は Web アプリと同じ
        try
        {
            await pdf.SaveAsync(Path.Combine(@"D:\out", customer.Id + ".pdf"));
        }
        catch (Exception ex) when (ex is HangaException || ex is IOException || ex is UnauthorizedAccessException)
        {
            // 失敗した帳票の扱い(飛ばす・止める・記録する)はバッチで決める
            Console.Error.WriteLine($"{customer.Id}: {ex.Message}");
            failures++;
        }
    }

    return failures == 0 ? 0 : 1;
}
```

- `HangaBatch` はバッチ全体で 1 つを共有します(スレッドセーフ)。`Cshtml2Pdf` は帳票 1 件ごとに作ります。
- `await using`(または `Dispose`)で終了すると、Chromium も終了します。生成中の帳票がすべて終わってから終了してください。
- ビュー名には `~/Views/Invoice/Invoice.cshtml` の形のパスも指定できます(その場合もコントローラー名は指定します)。
- `SaveAsync` は、同じフォルダの一時ファイルに書き終えてから名前を変えます。失敗・取り消しの場合は、保存先にファイルを作らず(既にあるファイルは変えず)、一時ファイルも残しません。
  保存先のフォルダはバッチで作っておいてください。
- PDF を作れなかった場合は `HangaException` の派生(「6. 例外」)になります。ファイルの書き込み・名前の変更の失敗(フォルダが無い、権限が無いなど)は、
  `IOException`・`UnauthorizedAccessException` がそのまま出ます(Hanga の例外に包みません)。
- 1 件の失敗(ビューの例外・ファイルの読み込みの失敗・タイムアウト)は、後の帳票に影響しません。帳票の生成の合間に Chromium が異常終了していた場合も、次の帳票で起動し直します。

### バッチ固有の設定(`HangaBatchOptions`)

| 名前 | 既定 | 内容 |
|---|---|---|
| `ViewAssemblies` | 空 | ビューを持つアセンブリ(帳票ライブラリ)。空なら自動で探す |
| `ContentRootPath` | バッチの実行ファイルのフォルダ | 相対パスの基準 |
| `WebRootPath` | `wwwroot` | 静的ファイルを置くフォルダ |
| `StaticFileMappings` | 空 | URL のパス → フォルダ の追加。例: `b.StaticFileMappings["/_content/Reports"] = @"D:\app\Reports\wwwroot";` |
| `ConfigureServices` | なし | ビューが `@inject` で使うサービス、ログの出力先、`WebEncoderOptions` などの登録 |

指定したフォルダ(`ContentRootPath`・`WebRootPath`・`StaticFileMappings`)が無い場合や、URL のパスが `/` で始まらない場合は、`StartAsync` で `HangaConfigurationException` になります。

### 速く生成するには(並行処理)

1 件の時間の多くは、表示の完了を確かめる待ち時間で、CPU をあまり使いません。帳票を並行して生成すると、1 件ずつより速くなります
(この開発環境での計測: 1 件ずつ約 1.2 秒/件、8 件を並行して約 0.4 秒/件。`.kiro/specs/batch-pdf-generation/design.md`「処理時間の目安」)。
Chromium での処理は `MaxConcurrentRenders` 件までに制限されます(「同時に処理する帳票の数の決め方」)。

ビューの HTML 化は、その制限の手前で行われます。数千件を一度に始めると全件のモデルと HTML が同時にメモリに載るため、並行数を `MaxConcurrentRenders` の 2 倍程度に抑えてください。

```csharp
using var slots = new SemaphoreSlim(options.MaxConcurrentRenders * 2);
var tasks = customers.Select(async customer =>
{
    await slots.WaitAsync();
    try
    {
        var pdf = new Cshtml2Pdf(batch, "Invoice", "Invoice", BuildInvoiceModel(customer));
        await pdf.SaveAsync(Path.Combine(outputDir, customer.Id + ".pdf"));
        return (customer.Id, Error: (Exception?)null);
    }
    catch (Exception ex) when (ex is HangaException || ex is IOException || ex is UnauthorizedAccessException)
    {
        return (customer.Id, Error: (Exception?)ex);
    }
    finally
    {
        slots.Release();
    }
});
var results = await Task.WhenAll(tasks);   // 失敗した帳票の扱いはバッチで決める
```

### その他

- 数値・日付の書式は、バッチのスレッドのカルチャで決まります。Web アプリと同じ書式にするには、バッチの開始時に
  `CultureInfo.DefaultThreadCurrentCulture = new CultureInfo("ja-JP");` などを設定してください。
- 帳票ライブラリに分けず、Web アプリのプロジェクトのビューを使う場合は、バッチから Web アプリのプロジェクトを参照し、
  `StaticFileMappings`(または `WebRootPath`)で Web アプリの `wwwroot` を指定します。ビューが Web アプリの `_Layout.cshtml` やサービスに依存する場合は、それもバッチで用意する必要があります。
