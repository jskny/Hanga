# Hanga 製品概要

## 目的

自社システムで使用する帳票(見積書・請求書・納品書など)を、**CSHTML(Razor)テンプレートとデータからPDFとして生成する**、
.NET 5 / C# 向けのライブラリを提供する。

帳票のレイアウトはHTML/CSSで記述し、差し込む値はC#のモデル(POCO)として渡す。
呼び出し元プロダクトは「テンプレートを指定し、モデルを渡し、PDFを受け取る」だけで帳票を出力できることを目指す。

「Hanga(版画)」という名前は、版(テンプレート)を一度作れば、そこにインクを載せる(データを差し込む)ことで
同じ体裁の刷り物(PDF)を何枚でも刷れる、という製品の役割に由来する。

## 姉妹プロダクト Utsushi との関係

同じ呼び出し元プロダクト向けに、Excel帳票をPDF化するライブラリ Utsushi(`jskny/Utsushi`)がある。

| | Utsushi | Hanga |
|---|---|---|
| 帳票の原本 | 既存のExcelファイル | CSHTML(Razor)テンプレート |
| 主な目的 | 既存帳票の見た目を崩さず「写す」 | HTML/CSSで新しく書いた帳票を「簡易的に」刷る |
| 値の差し込み | 指定セルの文字列置換 | Razor構文によるモデルの埋め込み(繰り返し・条件分岐を含む) |

両者は独立したライブラリであり、互いに参照しない。実行環境・技術的な制約(.NET 5、VS2019、無償OSSのみ)は共通とする。
既存のExcel帳票の置き換えはHangaの目的に含めない(既存帳票のPDF化はUtsushiの役割)。

## 対象範囲

- **対象**: 呼び出し元のASP.NET Core MVCアプリが持つビュー(`.cshtml`。レイアウト `_Layout.cshtml`、`ViewData`、`~/` のパス、タグヘルパーを含む、画面と同じ書き方のもの)。
  明細行の繰り返し、合計欄、条件による表示切替など、帳票によくある構造を扱えること。
- **主な使い方**: コントローラーにPDF用のアクションを追加し、オペレーターがそれを呼ぶと、画面と同じビューをPDFにしたものを受け取る(ブラウザのPDF印刷が使えない環境での代用)。
- **将来の使い方(候補)**: バッチ処理で、顧客向け帳票などをビューから一括でPDFにする。HTTPリクエストの外で生成できることは検証済み(`docs/PDF出力方式検証レポート.md`「6.4」)。
- **対象**: テンプレートが `<link>`・`<script>` で読み込む外部リソース(呼び出し元のASP.NET Coreアプリがホスティングする静的ファイル)と、帳票の見た目に関わるJavaScriptの実行。
- **対象外**: 不特定の外部ユーザーが自由に記述・アップロードしたテンプレートの実行(Razorテンプレートは任意のC#コードを実行できるため、信頼できるテンプレートのみを扱う)。
- **対象外**: ブラウザと同等の完全なHTML/CSS互換。帳票の作成に必要な範囲のHTML/CSSが期待どおりに出力されればよい。
  利用できるHTML/CSSの範囲は、PDF出力方式の選定(`tech.md`「未決事項」)とあわせて決め、テンプレート作成者向けに文書化する。

## 要件の前提(利用部門の回答。2026年10月3日)

- **PDFにするビュー**: 画面用のビューと同じものを使う。一部の画面には印刷用のCSS(`@media print`)がある。
- **出力の範囲と体裁**: 画面の全体をPDFにする。用紙サイズ・向き・余白などは、Utsushi の `Excel2Pdf` のように、オプションで制御できるようにする。
- **JavaScript**: ビューのJavaScriptが、サーバーから非同期で値を取得している可能性がある(扱いは `tech.md` の未決事項)。
- **外字**: 対応する(人名・住所の外字・異体字)。
- **性能**: 当面はベストエフォート。ただし、速度が出やすい実装にする。
- **PDFの返し方**: ブラウザでそのまま開く形と、ダウンロードさせる形の両方に対応する。
- **バッチでの一括生成**: 将来の候補。要件への取り込みは次回以降のセッションで行う。

## 解決する課題

- 帳票ごとにPDF描画コード(座標指定での文字・罫線の描画など)を書くと、作成・修正のコストが高い。
- 商用の帳票ツール・PDFライブラリはライセンス費用が発生し、自社の利用規模では採用しにくい。
- HTML/CSSとRazorで帳票を書ければ、Webアプリの画面と同じ知識・道具で帳票を作れる。

## 基本方針

1. **簡易さを優先する**: 呼び出し側のAPIとテンプレートの書き方を、少ない概念で使える形に保つ。高度な組版(段組み・脚注・複雑な改ページ制御など)は追わない。
2. **無料・自己完結**: 商用ライブラリおよびOffice Interop(COM)に依存しない。OSS(MIT/Apache-2.0/BSD等の永続的に無料で利用できるライセンス)のみを利用する。
3. **テンプレートの追加で帳票を増やす**: 新しい帳票への対応は、可能な限りライブラリのコード変更ではなく、テンプレート(とモデル)の追加で完結させる。
4. **失敗を黙って握りつぶさない**: テンプレートのコンパイルエラー、モデルの型の不一致、PDF出力の失敗などは、原因が分かる例外として呼び出し元に知らせる。

## 成功基準

- 登録したCSHTMLテンプレートとモデルから、呼び出し元プロダクト(.NET 5)のプロセス内でPDFを生成できること。
- 明細行の多い帳票で、複数ページにまたがって出力できること(改ページの扱いは要件定義で具体化する)。
- テンプレートが読み込む外部リソースとJavaScriptが反映された状態でPDFになること。読み込みに失敗した場合は、崩れたPDFを出さずにエラーとして知らせること。
- 日本語(帳票で使う日本語フォント)が正しく表示され、PDF内の文字列検索・コピーができること。
- Office・Excel・商用ライブラリなしに、サーバー/CI環境で生成処理が実行できること。
- 実行時・ビルド時に商用ライセンスが一切発生しないこと。

## 非対応(スコープ外)

- 信頼できない第三者が書いたテンプレートの実行(サンドボックス化は行わない)
- インターネット上のリソース(CDN等)の取得を前提とした帳票(既定では遮断する。`tech.md`「外部リソースの扱い」)
- ブラウザと同等のHTML/CSS/JavaScriptの完全な再現
- 既存のExcel/Word帳票の読み込み・変換(Excel帳票はUtsushiの役割)
- PDFの編集・結合・電子署名など、生成以外のPDF操作
- 帳票デザイナーなどのGUIツール
